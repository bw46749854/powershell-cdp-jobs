# 運用手順

週次・月次の作業を実行し、結果を確認する手順です。設定の意味は [configuration.md](configuration.md)、エラーの対処は [troubleshooting.md](troubleshooting.md) を参照してください。

## 1. 共通の準備

1. ブラウザ（Edge / Chrome）を**リモートデバッグ付き**で起動する（[getting-started.md](getting-started.md#3-本番の画面で動かす前に)）。
2. 対象の画面を**1つのタブだけ**で表示する。
3. ジョブの実行中は、そのブラウザを操作しない（スクロール・クリック・タブの切り替えをしない）。

ジョブは画面識別に一致するタブを自分で探して接続します。どのタブを前面にしておくかは関係ありません。

## 2. 週次: 土壌分析対象の整合

| 項目 | 内容 |
|---|---|
| 入口 | `週次_土壌分析対象の整合.bat`（ジョブ `WeeklySoilAnalysisSync`） |
| 対象の画面 | 温室コンソールの「区画」一覧。グループは「全区画（既定）」、絞り込み欄は空 |
| 所要時間の目安 | 区画数 × 1 秒程度 |

### 流れ

1. `PlotRosterExport` が「操作」→「CSV出力」で区画一覧をダウンロードし、`plot_roster_MMdd.csv` として保存する。
2. `SoilAnalysisTargetSync` がその CSV を読み、区画ごとに ON / OFF を判定する（判定ルールは [soil-analysis-target-sync.md](../jobs/soil-analysis-target-sync.md#判定ルール)）。
3. 判定できない行が1件でもあれば、**画面に触れずに**止まる。
4. 画面の件数が CSV の行数と一致することを確かめてから、一覧を上から順にチェックを ON / OFF に揃える。
5. 「土壌分析を依頼」が有効になったことを確かめる（**クリックはしない**）。

### 結果の確認

| 出力 | 場所 | 確認すること |
|---|---|---|
| 区画一覧 CSV | `work\weekly\downloads\plot_roster_MMdd.csv` | 同じ日に2回実行すると `plot_roster_MMdd (1).csv` になる |
| CSV データエラー一覧 | `work\weekly\downloads\soil_analysis_csv_errors.csv` | **あれば**、判定できなかった行。元の画面のデータを確認する |
| チェック整合失敗一覧 | `work\weekly\downloads\soil_analysis_sync_failures.csv` | **あれば**、揃えられなかった区画と理由（`Code` 列） |

失敗一覧は0件のとき作られません（前回の一覧があれば削除します）。ファイルがないことが「失敗なし」を表します。

正常終了したら、画面で選択された区画を確認し、担当者が「分析」→「土壌分析を依頼」を押します。

### 失敗したとき

- **チェック操作の前に止まった**（CSV データエラー、件数の不一致、画面の契約違反）: 画面は変わっていません。原因を直して再実行します。
- **チェック操作の途中で止まった**: 一部の区画のチェックだけが変わっている可能性があります。原因を直して**再実行してください**。ジョブは毎回 CSV の判定に揃えるため、何度実行しても結果は同じです（揃っている区画は「変更不要」として触りません）。
- 「土壌分析を依頼」を押すのは、ジョブが正常終了した後だけにします。

## 3. 月次: 定植レポート

| 項目 | 内容 |
|---|---|
| 入口 | `月次_定植レポート.bat`（ジョブ `MonthlyPlantingReport`） |
| 対象の画面 | 作付け台帳の「区画一覧」 |
| 実行する日 | 月初（「先月」は実行した日の前月の1日〜末日） |
| 所要時間の目安 | 区画数 × 3 秒程度 |

### 流れ

1. 実行ごとのフォルダー `work\monthly\runs\yyyyMMdd_HHmmss\` を作る。
2. `PlantingRecordExport` が区画を1つずつ開き、「作付け記録」タブの「CSV出力」で記録をダウンロードし、`planting_yyyyMMdd_<区画コード>.csv` として `planting_export_downloads\` に保存する。
3. 一覧の件数ぶん保存できたことと、失敗が無いことを確かめる。
4. `LastMonthPlantingDigest` が `planting_export_downloads\` の CSV を読み、先月に定植した作付けを `last_month_plantings.csv` にまとめる。

### 結果の確認

| 出力 | 場所 | 確認すること |
|---|---|---|
| 区画ごとの作付け記録 | `...\planting_export_downloads\planting_*.csv` | 区画数と同じ件数 |
| 保存の失敗一覧 | `...\planting_export_downloads\failed_planting_exports.csv` | **あれば**、保存できなかった区画（この場合ジョブは異常終了する） |
| 先月の定植 | `...\planting_export_downloads\last_month_plantings.csv` | 該当が無くても見出し行だけのファイルができる |
| 集計の失敗一覧 | `...\planting_export_downloads\last_month_plantings_failures.csv` | **あれば**、読めなかったファイル・行（定植日の空欄など）。集計自体は正常終了する |

### 失敗したとき

- 保存の途中で止まった場合も、再実行すれば新しい実行フォルダーで最初からやり直します。前回のフォルダーは集計に混ざりません。
- 集計の失敗一覧に載った行は、元の記録（作付け台帳）を直してから再実行するか、一覧を見て手で補います。

## 4. ログ

- 実行中の様子はコンソールに表示されます。各行は `[日時] [レベル] [実行ID] メッセージ` の形です。
- ファイルにも残すときは `Common.Logging.File = $true` にします（`logs\<ジョブ名>_<実行ID>.log`、UTF-8）。
- ページ操作の結果は `Data` として JSON で記録されます。止まった理由を調べるときに使います。

## 5. 片付け

`work\` は git の管理外です。次のものは自動では消えないため、必要に応じて削除してください。

- `work\monthly\runs\` の古い実行フォルダー
- `work\weekly\downloads\` の古い区画一覧 CSV

一時ダウンロード先（`work\weekly\tmp\...`、各実行フォルダーの `planting_export_tmp\`）は、ジョブが毎回空にしてから使います。

## 6. してはいけないこと

| してはいけないこと | 理由 |
|---|---|
| 実行中にブラウザを操作する | 表示中の行・開いている詳細が変わり、照合に失敗する |
| 同じ画面を2つのタブで開く | どちらを操作すべきか決められないため停止する |
| 普段使いのプロファイルでリモートデバッグを有効にする | 他のサイトのタブも自動操作の候補に入る。専用のプロファイルを使う |
| 出力先に、ユーザープロファイル直下やドライブのルートを指定する | 安全のため拒否される（一時ダウンロード先は中身を消すため） |
