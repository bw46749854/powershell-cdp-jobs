# 0002. ポートと合成ルート

- 状態: 採用
- 日付: 2026-11-05

## 状況

ジョブは、ファイル・時刻・ブラウザ・他のジョブといった外の世界に触れます。ジョブのコードがこれらを直接使うと、テストのたびに実ファイル・実時間・実ブラウザが必要になり、タイムアウトや失敗の経路を確かめられません。また、ジョブごとにファイル操作の安全確認や CSV の書式がばらつきます。

## 判断

- 外の世界への窓口を**サービス**（Log / Clock / Files / Downloads / Lists / Jobs / Browser）として実行基盤（JobHost）が実装し、`Context.Services` で渡します。
- 各ジョブは**合成ルート**（`Private/Ports.ps1`）で、使うサービスとメンバーだけを「ポート」として取り出し、形（メンバー名と必須のパラメーター名）を `Assert-PortShape` で検証します。
- Flow と純粋関数は Context を受け取らず、ポートと検証済みの設定値だけを受け取ります。ファイル・時刻・画面出力のコマンドを直接使いません。

## 理由と結果

- 偽のポート（`New-ScriptedPort`、`New-ManualClock`）で、Flow の全経路を実時間を待たずにテストできます。偽物も本物と同じ形の検証を通るため、形のずれは即座に失敗します。
- ファイル操作の安全確認（ルートやユーザープロファイルを消さない）、CSV の書式、ダウンロード完了の判定が実行基盤の1か所にまとまります。
- ジョブが何に依存しているかが、合成ルートの形の宣言を読むだけで分かります。
- 守ること: ジョブのモジュールは `JobKit` 以外を読み込まない、Context に触れるのは合成ルートとジョブコマンドだけ、I/O・時刻のコマンドを直接使わない。いずれもテスト（Architecture.Tests.ps1）で検査します。

## 検討した他の案

- **Pester の Mock でコマンドを差し替える**: テストはできますが、本物と偽物の形がずれても気づけず、ジョブが何に依存しているかもコードから読み取りにくくなります。
- **クラス（PowerShell の class）とインターフェース**: Windows PowerShell 5.1 のクラスはモジュールの読み込み順や再読み込みに制約が多く、scriptblock のポートの方が単純です。
