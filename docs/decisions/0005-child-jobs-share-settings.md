# 0005. 子ジョブは親と同じ設定で、同じ入口から動く

- 状態: 採用
- 日付: 2026-11-05

## 状況

週次・月次の作業は、既存のジョブを順に実行し、前のジョブの成果物を次のジョブへ渡す連携です。連携ジョブが子ジョブの関数を直接呼ぶと、設定の検証・Context の組み立て・結果の検証・ブラウザ接続の後始末を連携ジョブ側で再現する必要があります。また、親と子が別の設定ファイルを読むと、同じ連携の中で出力先やしきい値が食い違います。

## 判断

- 連携ジョブは `Jobs` サービスの `Run -JobName -Overrides` で子ジョブを起動します。`Run` は単独実行と同じ `Invoke-HostedJob` を呼びます。
- `Run` は設定ファイル・ジョブ定義のパスを受け取らず、常に親と同じものを使います。テスト用のサービスの差し替えも子ジョブへ引き継ぎます。
- 受け渡しは、子ジョブの設定の**この実行だけの上書き**（`Overrides`）で行います。上書きする値はパスなどの成果物の場所だけで、連携ジョブは CSV の中身を読みません。

## 理由と結果

- 子ジョブは単独実行と同じ検証・後始末を必ず通ります。単独で動くジョブは、連携の中でも同じように動きます。
- 親子で設定が食い違う状態を、構造上作れません。
- 連携ジョブは薄いままで、画面操作・解析・判定は子ジョブにだけあります。
- 子ジョブの設定を読む必要があるとき（月次の成果物の接頭辞など）は `Jobs.GetSettings` を使います。

## 検討した他の案

- **子ジョブのモジュールを読み込んで関数を直接呼ぶ**: 実行基盤の処理を再現する必要があり、モジュールの依存の向きも崩れます。
- **連携ジョブ用の設定ファイルを分ける**: 同じ値を二重に持つことになり、食い違いの原因になります。
