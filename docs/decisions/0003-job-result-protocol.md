# 0003. ジョブ結果の約束

- 状態: 採用
- 日付: 2026-11-05

## 状況

PowerShell の関数は、`return` した値だけでなく、パイプラインに出たすべての値を返します。戻り値を捨て忘れた呼び出しが1つあるだけで、ジョブの「結果」が配列になり、連携ジョブが別の値を成果物として読んでしまう危険があります。また、「失敗を表す結果」と例外が混在すると、呼び出し側が両方を確かめる必要があります。

## 判断

- ジョブコマンドは `New-JobResult` で作った結果（`Job` / `Ok` / `Outputs` / `Summary`）を**ちょうど1つ**返します。
- 失敗は例外で表します。`Ok = $false` の結果は約束違反とします。
- 実行基盤は `Assert-JobResult` で、出力が1つであること・ジョブ名が一致すること・`Ok` が `$true` であることを確かめます。連携ジョブも子ジョブの結果を同じ関数で確かめます。
- 後続のジョブが使う値は `Outputs`、件数などの記録は `Summary` に分けます。

## 理由と結果

- 出力の漏れは「結果が2つ」として、その場で検出されます（`[void]` の付け忘れに気づける）。
- 呼び出し側は「例外が出なければ成功」とだけ考えればよく、連携ジョブは `Outputs` だけを読みます。
- 区画ごとの失敗のように「最後まで処理してから失敗にする」場合は、失敗一覧を出力してから例外を投げます。

## 検討した他の案

- **成功・失敗の両方を結果オブジェクトで返す**: 呼び出し側の確認が二重になり、例外と結果のどちらで失敗が来るかを常に意識する必要があります。
- **戻り値の最後の要素を結果とみなす**: 漏れた出力を黙って捨てるため、誤りに気づけません。
