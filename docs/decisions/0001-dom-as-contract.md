# 0001. 画面の DOM を契約とみなす

- 状態: 採用
- 日付: 2026-11-05

## 状況

ジョブが操作する業務画面は、こちらの管理外で更新されます。更新のたびにジョブが止まるのは困りますが、変更に合わせて「それらしい要素」を推測で選ぶと、別の区画のチェックを外す・別の画面の CSV を保存する、といった取り違えが起きます。取り違えは、止まることよりはるかに大きな損害になります。

## 判断

画面の DOM を、意味と構造に分けて扱います。

- **意味**（製品名、メニュー・ボタン・タブ・列見出しの名前、`aria-selected` などの状態、画面が用意した `data-*` の目印、件数）は契約です。厳密に確かめ、対象が**ちょうど1つ**に決まらなければ止まります。
- **構造**（タグ、CSS クラス、ラッパー要素、列の並び順、固定列と通常列の区別）は契約に含めません。意味から候補を集めることで、多少の違いを吸収します。

止まるときは、満たしていない条件の名前・説明・候補の要約をログに出し、どこが変わったかを特定できるようにします。

## 理由と結果

- 取り違えの危険がある変化（意味の変化）では必ず止まり、無害な変化（構造の変化）では止まらない、という区別を、コードの書き方（`kit.locate.unique` と意味による探索）として強制できます。
- 各ページスクリプトの冒頭に「契約（意味）」「吸収する構造の違い」を書き、テストで記述の存在を確かめます。ブラウザスクリプトのテストでは、構造を変えた DOM で通ること・意味を変えた DOM で該当の条件だけが失敗することの両方を確かめます。
- 画面識別もこの契約で行うため、似た別の画面（別のグループ、別の一覧）を開いているタブには接続しません。

## 検討した他の案

- **CSS セレクタや XPath で要素の位置を固定する**: 構造の小さな変化で止まり、逆に位置がたまたま合えば別の要素を操作してしまいます。
- **見つからなければ近い要素で代用する（あいまい一致）**: 止まる回数は減りますが、取り違えを検出できなくなります。
- **画面の更新ごとにジョブを直す前提にする**: 構造の変化まで追従が必要になり、保守の負担が大きくなります。
