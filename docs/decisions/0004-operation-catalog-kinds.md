# 0004. 操作カタログと操作の種類

- 状態: 採用
- 日付: 2026-11-05

## 状況

PowerShell からページのヘルパーを呼ぶとき、ヘルパーが無い（画面が再読み込みされてスクリプトが消えた、カタログとスクリプトの名前がずれた）場合の扱いを、呼び出しごとに決めるとばらつきます。例えば一覧の読み取りで「ヘルパーが無い」を空の一覧として扱うと「0件」と誤認し、待機の条件で例外にすると待機の意味が無くなります。

## 判断

- ジョブごとに**操作カタログ**（`PageOperations.psd1`）で、PowerShell 側の操作名とヘルパーのメソッド名を対応させます。PowerShell のコードにメソッド名や JavaScript を書きません。
- 各操作に**種類**（`Kind`）を付け、種類ごとに「許される呼び出し方」と「ヘルパーが無いときの扱い」を一律に決めます。

  | Kind | 呼び出し | ヘルパーが無いとき |
  |---|---|---|
  | Identity | Invoke | 契約失敗の結果（そのタブは不一致） |
  | Contract | Assert | 契約失敗の結果 |
  | Action | Invoke | 続行不能の例外 |
  | Query | Invoke / WaitFor | 続行不能の例外（0件と区別する） |
  | Probe | WaitUntil | `false`（待ち続ける） |
  | Cleanup | Invoke | warning の結果（後始末を壊さない） |

- 注入の時点で、ヘルパーのメソッド一覧（`ack`）とカタログを照合します。テストでもカタログのメソッドがスクリプトにあることを静的に確かめます。

## 理由と結果

- 「ヘルパーが無い」ときの振る舞いが、操作の意味に沿って必ず同じになります。
- 契約（Contract）を Invoke で読み捨てる、といった誤用は設定の誤りとして止まります。
- 画面の部品と PowerShell の業務の流れが、カタログという1枚の表だけでつながるため、どちらかを直したときの影響範囲が分かります。

## 検討した他の案

- **呼び出しごとに引数で扱いを指定する**: 指定の付け忘れ・誤りが起き、レビューで見落としやすくなります。
- **PowerShell から JavaScript の式を直接書いて評価する**: 画面の知識が PowerShell 側に散らばり、ブラウザスクリプトのテストで確かめられなくなります。
