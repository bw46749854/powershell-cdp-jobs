# 設計判断の記録

なぜその形にしたのかを残す文書です。コードを読んで「なぜこうしないのか」と思ったら、まずここを見てください。判断を変えるときは、既存の記録を書き換えずに新しい記録を追加し、古い記録の「状態」を「置き換え（→ 新しい番号）」にします。

| 番号 | 判断 | 状態 |
|---|---|---|
| [0001](0001-dom-as-contract.md) | 画面の DOM を契約とみなし、意味の変更は吸収せず、構造の軽微な変更は吸収する | 採用 |
| [0002](0002-ports-and-composition-root.md) | ジョブは「ポート」からだけ外の世界に触れ、ポートは合成ルートで組み立てる | 採用 |
| [0003](0003-job-result-protocol.md) | ジョブはちょうど1つの結果を返し、失敗は例外で表す | 採用 |
| [0004](0004-operation-catalog-kinds.md) | ページ操作を操作カタログで宣言し、種類（Kind）で扱いを一律に決める | 採用 |
| [0005](0005-child-jobs-share-settings.md) | 連携ジョブの子ジョブは、親と同じ設定・ジョブ定義で、単独実行と同じ入口から動く | 採用 |
| [0006](0006-windows-powershell-5-1.md) | 本番は Windows PowerShell 5.1 とし、追加のインストールを要求しない | 採用 |
| [0007](0007-vendored-test-tools.md) | テスト用の Pester をリポジトリに同梱する | 採用 |

## 書き方

```markdown
# 番号. 判断の名前

- 状態: 採用 / 置き換え（→ 番号）
- 日付: YYYY-MM-DD

## 状況
何が問題だったか。どんな制約があったか。

## 判断
何をすることにしたか。

## 理由と結果
なぜそうしたか。その結果、何が楽になり、何を守る必要が生じたか。

## 検討した他の案
採らなかった案と、その理由。
```
